# Baseline Observations

- Image size in bytes: `380984592` (from `docker image inspect image-lab:baseline --format '{{.Size}}'`; ≈ 380.98 MB / 363.3 MiB)
- Largest non-base instruction and evidence: `COPY . .` — 8.44MB. `docker image history image-lab:baseline` shows the layers contributed by `Dockerfile.baseline` itself (as opposed to the layers already baked into the `python:3.12-bookworm` base image): `WORKDIR /app` (8.19kB), `COPY . .` (8.44MB), `RUN python -m compileall /app` (1.25MB), `EXPOSE`/`CMD` (0B). The `COPY . .` layer is by far the largest of these because the build context includes `reports/test-data.bin`, an 8MB binary file (`ls -la reports/test-data.bin` → 8388608 bytes) that accounts for nearly all of that layer's weight.
- Configured runtime user: `""` (empty string) from `docker image inspect image-lab:baseline --format '{{json .Config.User}}'`. `Dockerfile.baseline` never declares a `USER` instruction, so the empty value means the container falls back to the image default, which is `root`.
- Unnecessary copied file or directory 1: `reports/` — contains `reports/test-data.bin` (8MB) and `reports/coverage.txt`, both explicitly labeled reference-only ("Reference-only coverage output. The running API does not need this file.") and never read by `app.py`.
- Unnecessary copied file or directory 2: `tests/` — contains `tests/test_app.py`, a unit test module for `payload_for()` that is only useful at development/CI time and is never imported or executed by the running `ThreadingHTTPServer` in `app.py`. (`docs/architecture.md` and `local-notes.txt` are also copied and unused, for the same reason.)

## Evidence-Based Optimization Targets

1. **Add a `.dockerignore` to shrink the build context and the `COPY . .` layer.** Evidence: the `COPY . .` layer measured 8.44MB via `docker image history`, and `reports/test-data.bin` alone is 8388608 bytes (`ls -la`) — roughly 95% of that layer's size — despite the app only ever serving `/health` and `/items` from `app.py`. `docs/`, `reports/`, `tests/`, and `local-notes.txt` are all copied into the immutable image layer even though none are referenced at runtime.
2. **Replace the full `python:3.12-bookworm` base image with a smaller, purpose-built variant.** Evidence: `docker image history --no-trunc` shows the base image itself contributes large layers unrelated to running a stdlib HTTP server, e.g. a 619MB layer installing a full build toolchain (`autoconf automake gcc g++ make libssl-dev libpq-dev libmysqlclient-dev …`), a 194MB layer installing `git`/`mercurial`/`subversion`, and a 133MB `debian.sh` rootfs layer. `app.py` uses only `http.server` and `json` from the standard library and needs no compiler or VCS client at runtime, so this weight is pure overhead carried into the final 380,984,592-byte image.
3. **Set a non-root `USER` for the runtime container.** Evidence: `docker image inspect --format '{{json .Config.User}}'` returned `""`, confirming no `USER` instruction exists in `Dockerfile.baseline`, so the container runs the HTTP server as `root` by default — unnecessary privilege for a process that only binds port 8080 and serves static JSON.
